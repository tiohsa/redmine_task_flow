# Redmine Task Flow

A Redmine plugin that provides a visual DAG task flow editor and bulk issue/relation creator.

## Features

- **Visual DAG Editor**: Create task nodes, group (parent issue) nodes, and `precedes` dependency edges on an interactive canvas (`@xyflow/react`), with `dagre` auto-layout and Undo/Redo support.
- **Dependency & Schedule Preview**: Prevents cyclic dependencies, propagates calendar dates across `precedes` edges (supporting `delay`, locked dates, base date, and estimated-hours conversion), and rolls up dates/hours to parent groups.
- **Redmine-Aware Inspector**: Edits issue attributes while respecting Redmine tracker `disabled_core_fields`, allowed statuses, assignees, target versions, and visible custom fields.
- **Transactional Bulk Creation**: Creates issues in topological order along with parent-child links and `IssueRelation` (`precedes`) records inside a single database transaction, rolling back all changes on validation errors.
- **Draft Persistence & JSON I/O**: Auto-saves drafts to `localStorage` and supports JSON export/import.
- **Security**: Uses Redmine's session authentication, CSRF protection, and `Issue#safe_attributes=`, without exposing user API keys.

## Requirements

- Redmine 6.0, 6.1, or 7.0 (`requires_redmine version_or_higher: '6.0.0'`) and a Ruby version supported by that Redmine release.
- Enable the **Task Flow** (`task_flow`) module on target projects.
- Users must have all three permissions:
  - `create_issues_via_flow`
  - `add_issues`
  - `manage_issue_relations`

No plugin-specific gems or database migrations are required. Prebuilt frontend bundles (`assets/javascripts/task_flow.js` and `assets/stylesheets/task_flow.css`) are included in the repository.

- [Redmine releases](https://www.redmine.org/projects/redmine/wiki/Download)
- [Redmine runtime requirements](https://www.redmine.org/projects/redmine/wiki/RedmineInstall)

## Installation

1. Place this directory at `plugins/redmine_task_flow` in your Redmine installation.
2. Restart Redmine.
3. Enable the **Task Flow** module in **Project Settings → Modules** and grant `create_issues_via_flow`, `add_issues`, and `manage_issue_relations` to the appropriate roles.

## Development & Frontend Build

The frontend is built with React 18, TypeScript, Vite, Tailwind CSS (`.task-flow-root` scoped), Zustand, `@xyflow/react`, and `dagre` under `frontend/`.

To rebuild the plugin assets after editing `frontend/src/`:

```bash
cd frontend
npm install
npm run build        # runs tsc -b && vite build -> assets/
# or
npm run build:watch  # watch mode
```

Do not edit `assets/javascripts/task_flow.js` or `assets/stylesheets/task_flow.css` directly; they are generated by `npm run build`.

When developing with the parent Docker Compose environment (`../../docker-compose.yml`, Redmine 7.0.2 at `http://localhost:3000`), restart the `redmine` service after updating Ruby files, routes, views, or built assets:

```bash
docker compose -f ../../docker-compose.yml up -d
docker compose -f ../../docker-compose.yml restart redmine
```

## Tests

### Frontend (Vitest)

```bash
cd frontend
npm test
```

### Backend (Minitest)

> **Prerequisite:** The parent `../../docker-compose.yml` defaults to `RAILS_ENV=production` and does not define a `test` database in `config/database.yml`. Configure and prepare a separate `test` database in Redmine's `config/database.yml` before running backend tests.

From the Redmine root:

```bash
RAILS_ENV=test bundle exec rails test plugins/redmine_task_flow/test
```

Or inside the Docker Compose `redmine` container (from `plugins/redmine_task_flow`):

```bash
docker compose -f ../../docker-compose.yml exec -e RAILS_ENV=test redmine bundle exec rails test plugins/redmine_task_flow/test
```

Browser verification against a running Redmine instance (e.g. `http://localhost:3000`) should also be performed for UI flows, persistence, and permission checks.
